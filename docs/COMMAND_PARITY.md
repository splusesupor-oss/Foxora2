## Wired in the new runtime

### Global-owner broadcast

- Exact triggers: `اطلاع رسانی`, `اطلاعرسانی`, and `اعلان`. The current sender must pass the canonical global-owner registry check; group ownership and group-admin status do not grant this capability. The origin group must be active and registered locally. It is routed after existing source-ordered public/admin commands and before the final message-filter pipeline, so a help/admin command already handled by an earlier route is not consumed as announcement text.
- The workflow is bound to the owner and origin group and expires after ten minutes. It captures the message text and supported SPlusthon formatting entities, performs a complete local `group_registry` scan capped at 5,000 rows, then shows a preview and exact active-target count. If the scan exceeds the cap or cannot complete, the session is cleared and nothing is sent. No source group list or identifier is imported.
- No outbound broadcast occurs before `تأیید` / `تایید` / `✅ تایید`; `لغو` / `❌ لغو` cancels. At confirmation, the full active set is scanned again and must exactly match the preview. Each target is then checked again immediately before its individual message send. A changed/incomplete set at confirmation aborts with no broadcast.
- Each group text is a separate `SPlusthonAdapter.send_group_message` call through the process-wide `SerialRpcQueue`, awaited sequentially with retries disabled. The installed `SoroushClient.send_message` signature exposes `formatting_entities`; local tests verify that API shape without logging in or sending. The adapter fails when the platform returns `None`, `False`, or an empty scalar; only returned platform responses are counted as confirmed. Failed/uncertain sends are aggregated, not logged per message. Messages are never merged or sent concurrently; other queued groups retain the queue's round-robin fairness.
- If the process is interrupted during delivery, the persisted `sending` state prevents automatic replay. The global owner must explicitly clear that uncertain local state with `لغو` in the original group before starting a new preview; already-sent targets are not automatically resent. Unit tests use only a fake platform. No live broadcast or Soroush delivery was attempted.

### Group filter / word-list commands

- `/فیلتر <word>`
- `/رفع <word>`
- `/فیلترها`
- `!addword <word>`, `!addban <word>`, `!افزودن <word>`
- `!remword <word>`, `!removeword <word>`, `!حذف <word>`
- `فعال کلمات ممنوعه`
- `لغو کلمات ممنوعه`

The legacy `!addword`/`!remword` aliases are deliberately restricted to the current group in this port. The global banned-word file is not modified from a group command. The strict toggle is persisted per group; disabling it leaves the group's manual filter terms active. Group-admin checks also recognize ID-based source `admins.json` rows and legacy username-only strings through the optional read-only `FOX_LEGACY_ADMINS_FILE` (default `config/admins.json`); a matching sender is promoted to a stable local user-ID record on first message. Missing/malformed legacy files fail closed, and the source file is not edited. The global strict matcher now supports the source's Arabic/Persian lookalike folding, repeated-letter forms, and separators inserted between letters, while retaining the exact user-supplied terms and their original spelling. Fuzzy matching is bounded to the first 8,000 code points to control CPU; source behavior on unusually long text beyond that prefix is not claimed. Manual group terms remain a distinct list and are not expanded by this global matcher. Each group's manual list is bounded to 256 terms, 256 code points per term, and 64 KiB; route patterns are compiled only when the list changes, and manual-word matching scans the first 8,000 code points for CPU bounds. `/فیلترها` sends sequential pages capped at 3,500 UTF-16 code units. A stored list above these limits fails closed at startup rather than being silently truncated; authorized admins can prune it with the existing removal command.

Message-level moderation now records a durable automatic warning for an authorized `WordFilter` hit and applies the group's existing threshold/punishment mode (default: five warnings, then ban) only through fresh membership/role checks and a platform-verified result. The counter is reset only after a verified action; no admin actor is fabricated. If a delete RPC fails, the warning remains, but the notice explicitly says deletion was not confirmed rather than claiming success. Warning notices are rate-limited per user/group.

A clean-room `SpamGuard` is wired before command/filter dispatch for new group messages. State is bounded and isolated by `(group,user)`; commands and trusted registered owners/admins/VIPs do not seed the detector. Platform-native admins are checked through a short-lived single-flight cache, and unknown native-admin status fails closed without seeding an incident. It covers: similar promotional waves (two strong similar posts, or four consecutive identical short promo tokens within 60 seconds; direct ban); three meaningful normalized repeats within 30 seconds (direct ban); a separate four-copy/ten-second flood fingerprint (direct ban) that collapses stretched runs but preserves word spacing; packed/repeated promotional phrases and decorative-symbol spam in one post (direct ban); a word-filter hit paired with a >300-character payload containing fewer than 20 distinct whitespace tokens (direct ban, bounded to payloads no longer than 8,000 characters); three low-entropy posts within ten seconds and ten-message/ten-second floods using at most four payloads (direct ban); six consecutive GIFs without a two-minute cutoff (retain the first and delete the next five), then delete each later GIF while the one-hour flag is active; unflagged counters expire after one hour of inactivity; a one-hour mute is attempted once, and its success notice is sent only after platform verification, while the source-compatible GIF deletion flag remains active if mute verification fails. Repeat-key normalization preserves stretched letters; a distinct flood key performs the stretch folding. Promotional similarity uses the source's normalized similarity/phrase/marker signals but caps SequenceMatcher input at 256 code points per comparison to bound CPU, so long-caption similarity is not claimed as exact source parity. When `FOX_CHECK_FORWARDED=true`, genuine forward-header/flag metadata (not a `forwards` view count) triggers deletion and album-sibling cleanup; the third forward within ten minutes attempts a 24-hour mute. The setting defaults to false, matching the inspected snapshot config. Source admin-priority management commands bypass forward cleanup, while public commands such as `راهنما` remain subject to it. The source username/ad checks (two or more IDs, one ID paired with a source ad-context token, or one short under-50-character ID), conservative Iranian/international phone-number shapes, `@all`/`@everyone`/`@here` mentions, the source site-link policy, and the source live-ad emoji predicate are separate warning-level checks, not new banned-word entries; their deletion is confirmed before the warning is recorded. Username matching also recognizes the source `آیدی`/`ایدی`/`پی وی`/`پی‌وی`/`pv` prefixes. Email addresses are excluded from the local `@handle` match to avoid treating an email's domain as a public username. Site links are classified by hostname with blocked-domain precedence, exact/subdomain boundaries, trusted/search allowlists, and the real `splus.ir/meet/` exception; an unknown or blocked first URL creates a warning. The live-ad predicate requires `لایو`/`لایوه` or standalone `live` plus one of the six source emojis (`👙🍑🫦😈🍈🔯`). Both use bounded message prefixes and do not modify the user-approved global or group word lists. All actions are subject to fresh member/role checks and only recorded/notified after platform verification. A small set of ordinary greetings is exempted, and generic repeat/flood signals are suppressed during a live local game-answer session. Deletions use a bounded per-group worker with retry; the duplicate-flood notice is emitted only after all selected deletes are confirmed. Multi-step automatic moderation workflows use a separate bounded per-group FIFO queue, and their platform RPCs still pass one-at-a-time through the existing process-wide serial queue. Queue-capacity failures are fail-closed and leave the detector state retryable. Ordinary photo/video attachments are not classified as spam; the inspected active handler did not call its generic `check_media_spam` helper.

This is intentionally a limited parity slice, not a claim that every source detector has moved. Sender ad-name handling is now a bounded clean-room subset: with `FOX_CHECK_AD_NAMES=true` (default), non-command messages from confirmed non-admin/non-VIP users are screened by checking the first name, last name, and username against only the user-approved global matcher; a match queues the current group's ban/mute mode through the normal fresh-role and platform-verification path. The matched text is not echoed, no message deletion is claimed, and a per-user/group cooldown suppresses repeated action requests. The source-only ad-name term/regex corpus was not imported; its exact trigger coverage remains unported. Independent startup `FOX_*` controls cover links, phone numbers, usernames, forwarded messages, sender-name screening, global banned-word message filtering, deletion history, spam-warning notices, and the default warning threshold/action/duration; defaults match the inspected config values (`5`, ban, 3,600 seconds, and `FOX_CHECK_FORWARDED=false`). Persisted per-group threshold/action settings take precedence. Turning off `FOX_CHECK_BANNED_WORDS` skips global-word matching in message moderation while retaining group-specific manual terms and direct profile/name validation. Turning off `FOX_SEND_SPAM_WARNINGS` suppresses notices but still records warnings and applies the configured threshold action. `FOX_CONFIG_FILE` (default `config/config.json`) reads only an allowlist of typed, non-secret moderation switches and threshold/action values from files capped at 1 MB; environment variables take precedence. JSON credentials, word lists, warning text, and owner/admin/whitelist IDs are ignored. The source's general JSON config manager and config-file whitelist/admin lists remain unported. `FOX_HOT_RELOAD_BANNED_WORDS` (default on) watches only `FOX_GLOBAL_WORDS_FILE` and atomically replaces that matcher without importing or merging any source list; limits are 256 KiB, 2,048 terms, and 512 code points per term; an invalid update retains the last working matcher. `FOX_WARNING_MESSAGE` provides an environment-based template using only plain `username`, `reason`, `count`, and `threshold` fields (no conversions, nested fields, or format specs); display fields and final output are UTF-16-bounded, with deletion-confirmation status appended from the actual platform result. The global matcher reads only the user-approved file. Link detection classifies only the first extracted URL in a message, matching the active source's first-match behavior; a later URL can therefore remain unchecked if an earlier trusted URL appears first. The source-only ad-name term/regex corpus was not imported; the local sender-name screen uses only the approved global matcher behind `FOX_CHECK_AD_NAMES`, and the manual group-name list remains separate and is not merged or auto-enforced. No global or group word list was modified. Live SPlusthon authorization, delivery, delete semantics, and moderation verification still require a controlled group test.
