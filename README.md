## 🪶 کاهش‌بارِ خودکار (Load Shedding)

وقتی اتصالِ سروش کند شود یا صف‌ها سنگین شوند، ربات خودش کارهای کم‌اولویت را
موقتاً عقب می‌اندازد تا مدیریتِ حیاتی (بن/سکوت/حذف) و پاسخ‌های ضروریِ کاربر
قربانی نشوند:

* **تشخیص با زیرساختِ موجود:** سنِ منتظرانِ Governor، backlogِ سطحِ پایینِ
  sender، صفِ عادیِ dispatch و EMAِ زمانِ نگه‌داشتِ پرمیت — بدونِ هیچ RPC یا
  تسکِ جدیدی (`modules/load_shedding.py` فقط شمارنده‌های درون‌حافظه را می‌خواند).
* **hysteresis واقعی:** ورود بعد از چند نمونهٔ متوالیِ بالای آستانه و خروج بعد
  از چند نمونهٔ متوالیِ زیر آستانهٔ پایین‌تر + حداقل ماندگاری در هر حالت؛
  ربات بین دو حالت سوسو نمی‌زند. گذارها با `LOAD SHED ENTER/EXIT` لاگ می‌شوند.
* **مصرف‌کننده‌های فعلی:** اسکنِ دوره‌ایِ اعضا برای فیلترِ بیو
  (`bio_link_service.watcher`) و گزارشِ روزانهٔ ساعت ۲۳
  (`daily_admin_report`) حینِ کاهش‌بار راندهای‌شان را عقب می‌اندازند و بعد از
  عادی‌شدنِ خط ادامه می‌دهند؛ اسکنِ «هنگامِ پیام» و دستورهای دستی هیچ‌وقت
  معطل نمی‌مانند.
* **قابل‌خاموشی و تنظیم:** `BOT_LOAD_SHED=0` رفتار قبلی را برمی‌گرداند؛
  آستانه‌ها با `BOT_LOAD_SHED_*` در `.env` قابل‌تنظیم‌اند (`.env.example`).

همچنین جریمهٔ هوشِ مصنوعیِ تبلیغ‌گر دیگر پیامِ عمومیِ «⛔️ کاربر … به دلیل
اسپم مکرر از گروه حذف شد» را نمی‌فرستد؛ خودِ مجازات (حذف/سکوت/بن) بدونِ
اعلان اعمال می‌شود.

```bash
PYTHONPATH=. python3 tests/test_load_shedding.py   # ۲۸ بررسی
```
